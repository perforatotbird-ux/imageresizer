# imageresizer — современный Desktop UI / UI 01

## Что изменено

Русскоязычный интерфейс с тёмной боковой навигацией, светлыми панелями,
синим главным действием и отдельной сводкой результата. Четыре раздела:
«Папки», «Размер», «JPEG», «Движок». Параметры приложения не удалены.

- Сводка меняется вместе с размером, качеством, фильтром, геометрией, backend
  и политикой существующих результатов. Схема явно помечена как НЕ превью фото.
- Ввод ширины/высоты вручную переводит именованный preset в custom.
- Настройки блокируются на время выполнения; запуск, прогресс, отмена и
  ожидание завершения child process остаются в контроллере GUI.
- Журнал раскрывается отдельно, при ошибке открывается автоматически;
  проверка окружения также раскрывает журнал. Ошибки/отмена/успех различаются
  текстом и цветом; устаревшая надпись «готово к запуску» после ошибки не остаётся.
- Прокрутка доступна для длинных настроек и сводки, панели запуска остаются
  доступными при изменении размера окна. При крупном тексте действия переносятся
  ниже прогресса; toolbar также может переноситься на вторую строку.
- Добавлена предварительная проверка чисел, finite VRAM/scale, размера, фона и
  небезопасного отношения input/output до запуска child process.
- «Открыть результаты» не создаёт каталог как побочный эффект; отсутствие каталога
  и ошибка файлового менеджера показываются пользователю.

## Как именно использован Tkinter Designer

Реально использован код генератора из
https://github.com/ParthJadhav/Tkinter-Designer
на commit `61ce0665ce68e255fd8bead3c14aac6c877bfa05`.

Figma-файл и API-токен пользователя не предоставлялись. Вместо выдачи обычного
ручного GUI за результат Figma создан `design/desktop.json`: локальное подмножество
узлов Figma REST (это не `.fig` файл и не документ в аккаунте Figma).
Через `tkdesigner.figma.frame.Frame` и рендеринг элементов генератора созданы
два встраиваемых vector/text компонента: бренд-блок и основа схемы размеров.
Их код находится в `batchresize/ui_generated.py`, содержит attribution и
генерируется без сети/скачивания изображений. BSD-3-Clause лицензия сохранена
в `third_party/Tkinter-Designer-LICENSE.txt`.

Вместо фиксированного окна script-template использован компонентный шаблон.
Адаптивная компоновка, настоящие ttk-поля/кнопки, state images и bindings написаны
отдельно в `batchresize/ui_view.py`. Существующий `batchresize/gui.py` остаётся
контроллером, а не файлом, который генератор может затереть. Генератор не правит
конвейер обработки изображений.

Для запуска конечного GUI не нужны tkdesigner, Figma, requests, Jinja2, Pillow,
NumPy или CUDA в самом GUI-interpreter: достаточно Python с tkinter. Научный
стек нужен рабочему child-interpreter, как и до обновления интерфейса.
Pillow требуется только при захвате screenshots в диагностическом harness.

## Регенерация компонентов — только для разработки

В отдельном venv установить `requirements-ui-design.txt`, получить проверенную
копию Tkinter Designer и checkout указанного commit. Затем:

```sh
python tools/generate_desktop_design.py --designer-repo /path/to/Tkinter-Designer
```

Скрипт проверяет commit генератора и перезаписывает только ui_generated.py.
Он не очищает рабочий проект и не делает Figma API calls. Повторная генерация
на той же версии подтверждена побайтным сравнением.

## Проверки и ограничения

Реальные Tk-тесты выполнены на Linux с изолированными Python 3.13.16,
Tk 8.6.13 Xft и Xvfb. Среда установлена только в /data, не глобально; права
администратора и системные настройки не менялись. Для pipeline использованы
CPU-библиотеки проверенной среды аудита.

Итоговая полная suite: **153 passed, 24 skipped** (GPU недоступен).
Новая suite содержит 18 GUI cases; исходные тесты сохранены.
`tests/test_gui_modern.py` проверяет навигацию, все восемь quality
presets, summary, resize, блокировку контролов, запуск настоящей CPU-обработки
трёх synthetic images, verified resume, UTF-8 child IPC, кооперативную отмену,
автораскрытие ошибок, preflight, лёгкий import без site-packages и закрытие окна
после завершения child process. Тесты явно skip, если нет tkinter/display.

Визуальная проверка настоящего окна (не HTML-макета): четыре страницы и их нижние
части, 1220×900 и 1060×740, раскрытый журнал, ошибка и отдельный Xvfb display
144 DPI. Крупные шрифты, переносы и доступность нижних кнопок проверены.
Проверка Linux 144 DPI не подменяет реальную Windows HiDPI-приёмку.

Windows GUI, NVDA/accessibility, multi-monitor DPI transitions и NVIDIA/CUDA
в этом окружении не проверялись. Ограничения исходных исправлений IR-17/18/26
из FIX_REPORT остаются в силе. Обновление внешнего вида не является их закрытием.

## Запуск

В каталоге проекта на Windows:

```bat
install.bat --cpu
run.bat --gui
```

Если venv уже установлен, достаточно `run.bat --gui`.
Для NVIDIA используется существующий `install.bat` без --cpu, но совместимость
конкретной CUDA/driver/GPU конфигурации требует проверки. `--gui` использует
существующий механизм выбора interpreter с tkinter.

Обновление опубликовано как исходники, не как установочный EXE. Не копируйте
поверх своей папки фото/данных непроверенное содержимое; обновляйте код отдельно.
